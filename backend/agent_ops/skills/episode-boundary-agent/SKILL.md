# 下一集分集断点

本 Skill 负责当前项目的下一集原文范围及用户明确指定分集的修订，按项目目标字数（默认约 1000 字）划出一个完整的局部剧情单元，供后续视频片段制作使用。断点依据当前剧情的因果推进与局部结果。保留项目已有的集数、目标字数、资产覆盖和提交契约。用户本轮反馈与已接受的创作约束优先于一般写法建议；如果反馈含义不清、会改变对象或范围，先在对话中澄清。

## 读取与选择

1. 先确定本轮是规划下一集还是修订已保存分集。修订目标来自用户明确指定或本会话可核对的上一轮结果，不借用其他会话；不明确则澄清。调用 `get_episode_boundary_context(part="source_text")` 和 `part="planning_state"`，取得正文、集号、游标、目标字数、容差与允许边界；修订时每次都传同一 `episodeId`，并核对 `currentEpisode` 的原结果。两项的 `contextVersion` 必须一致，不一致则重读。资产覆盖由后端检查，阻断时说明原因，不绕过门槛。必要的旧约束用 `get_conversation_history` 查询当前会话，不猜游标或扫描本地业务文件。
2. 目标字数表示附近长度，不要求精确凑字。正常原文充足时，`sourceText` 会超过目标，供比较前后落点；其中 `sourceWindowEnd` 是已读原文末尾，`planningWindowEnd` 是可提交边界上限，两者可能因资产覆盖不同。后文可帮助理解，但不能据此越过覆盖门槛。先使用完整已读正文；确需更多后文才读 `continuation_text`，它从 `sourceWindowEnd` 起补充约 750 字。仍不足以解答明确问题时，才用通用 `read_source_window` 从尚未读到的位置补充；不能换偏移重复读。`search_source_text` 只定位明确事实，`get_source_coverage` 只调查覆盖阻碍。这些是读取用途要求，不限制合理请求次数。
3. 根据原文选择一个完整的当集落点：核对本集进入状态、关键行动及必要反应，确认已形成局部结果；集尾的后续压力不要求整条故事线结束。资产介绍结束、换行或达到字数不能代替此判断。对选定位置和紧接原文检查是否切掉理解本次行动所必需的结果，不能用标题或理由补出正文尚未发生的事实。允许区间内没有合格位置时说明冲突并停止，不机械截断或自行修改项目字数。
   信息揭示也可以形成局部结果：正文已给出当前问题的答案、限制、后果或明确的新处境，就不必等主角整条行动线成功／失败，也不必把对既有结论的所有讨论和情绪反应都收进本集。核对的是后文是否仍在完成这个结论，而不是它是否仍与此事有关。
   对连续的展示、对话或验证，应区分铺垫与结论。列举设定、对象评价、工具用途和准备手段本身不足以证明当集落点；紧接同一来源仍给出关键总结或改变前述信息含义的答案时，须纳入该结论，不能提前停在铺垫上。比较附近落点，选择实际完成本轮变化的位置；不要用本集前段已完成的旧事件为结尾仍在进行的另一局部单元辩护。上述检查与生成合并完成，不要求输出思考过程。
4. 为本集写能抓住**一个**记忆点的具体短标题，优先从核心场面、关键事件、认知转折、异常危机或关系变化中选择最鲜明的一项。标题应让未读者能理解、读后能记住，比剧情摘要更短更有辨识度；不要拼接多个事件、使用只有内部才懂的术语，或用泛泛的集号代替标题。`reason` 用一两句简短中文（建议 30–80 字），说明本集完成了哪个局部剧情结果，以及下一集如何自然承接；另列必要风险。标题和理由保留原文的信息确定程度：含混称谓、人物猜测或传闻不能改写成已确认的具体事件，不用常见故事套路补足原因；无关选点的推测直接省略。取断点末尾连续的 20–60 个有效字，原样放入 `boundaryEndText`；它必须唯一定位到已读原文的结尾。提交前检查引文与原文逐字一致、有效字数在范围内，不要只摘末尾几个字或重读已经拿到的 `sourceText` 来完成这项检查。

## 校验与返工

5. 完成上述内容自检后，调用 `submit_episode_boundary_candidate`，传 `boundaryEndText`、`episodeTitle`、`reason`、`riskNotes` 及两项读取共有的 `contextVersion`；修订时还需同一 `episodeId`，下一集规划省略它。失败按 `errors[].path` 与 `repairAction` 处理：`revise_payload` 定点修订，`refresh_context` 重读同一目标的正文和状态并重新检查，`stop` 说明阻碍。不能只更换版本字段沿用未经复核的旧结果。
6. 本轮目标绑定首次读取的集号和起点；刷新发现该目标已被其他操作推进或替换时，停止并说明冲突，不自动改为另一集，也不转成修订其他会话刚提交的结果。返回 `committed` 表示写入及回读已完成，停止本轮任务；本地程序从已保存断点提取本集结尾和下一集开头，各展示最多 100 字，并展示提交的断点理由。

## 反馈

7. 反馈只修订明确目标，保留未被替换的约束。只改标题／理由时，沿用 `currentEpisode` 的原尾句、未修改字段和风险，不重新选断点。明确调整边界时重新检查局部剧情和连续性；已有后续分集或下游内容阻碍修改时说明影响，不清除依赖，也不改为规划下一集。纯元数据修订不要求删除下游。不能将反馈当作确认指令。
8. 用户仅讨论方案、询问进度或目标不明确时正常回答或澄清，不擅自写入数据。
