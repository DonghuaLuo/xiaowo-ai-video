# 当前集剧情拆分

本 Skill 只处理当前分集会话绑定的那一集。按完整原文定位剧情段落，同时单独标注应从成品剧情中清理的非剧情内容；后端从候选生成工作链和画布。用户本轮要求及待确认候选的修改反馈是本次验收条件；含义不清或可能改变分集对象时先澄清。

## 1. 锁定分集与权威资料

先调用 `get_plot_split_context(part="source_text")`，只读取本会话绑定分集的完整已确认原文。建立剧情行动候选后，调用 `get_plot_split_context(part="asset_catalog")`，只读取本集可关联的四类已有资产 ID 与精简身份。来源范围、摘要及最终坐标由后端在提交时核验和推导，不混入原文读取结果。核对本轮用户要求和当前待确认候选的反馈；较早约束缺失时只查询本会话历史。若分集原文缺失、画布已有不可覆盖的正式工作链或目标不明确，停止并说明。原文是剧情事实的权威输入；相邻集只帮助理解人物和交接，不纳入本集拆分。不要扫描运行目录、开发源码或 Git。

**通过条件：**目标和可用资料明确，不把讨论、旧候选或别的分集当成这次任务。

## 2. 建立完整行动单元，再检验边界

通读本集，先识别每次主要行动的问题：谁要完成或弄清什么，经历了什么阻碍、反应与结果。草拟连续段落，再逐个检查交界：只有前一行动已有落点、后一行动围绕新的主问题展开自身过程和落点，或实际转场后开始新行动，才保留边界。同一地点或连续时间内也可以有两个各自完成的事件；同一行动的发现、阻碍、新人物进入、即时对话和直接后果应留在一起。

- 录像、直播、回忆、换屏、对白开始或第一次看见对象，只是表达形式或行动节点，不能单独成为切点。
- 记录后果、撤离、即时复核和交接准备通常属于前一行动收束；缺少新的独立障碍、决定与落点时不要另拆。
- 从后向前撤掉每个拟定边界试读：若仍是一条未中断的目标—阻碍—反应—结果因果链，就合并。再反向检查每段内部：若有两个主问题各自展开并落地，就切开。
- 标题用故事中的具体行动或转折概括，`splitReason` 简述本段主问题和与相邻段分界的原因，不能使用统一套话。段落数由故事决定，不按篇幅、镜头数或视频模型时长平均切。

**通过条件：**每段能说明自身行动与落点，交界可解释；既无把一个行动切碎，也无把多个独立事件吞并。

## 3. 单独清理非剧情插入内容

拆分时先判断文字在小说中的叙事作用，再决定是否清理。章节标题、章序等篇章标识，以及出版、推广、导流或联系作者/平台的广告、网址、联系方式等，若属于正文外插入内容，应从最终剧情正文中清理。被夹在剧情中间的外插内容也要清理，但不能因此切碎同一行动。判断依据是上下文、叙述视角、人物是否实际感知或使用该信息、它是否推动事件或构成设定；不能仅凭网址、号码、称呼或标题的字面形态删除。

- 小说人物在对白、屏幕、信件、广告牌等剧情内媒介中看到、说出或使用的网址、联系方式、广告和章名，若承担情节、人物或世界设定作用，保留原文。存疑且无法确认是正文外插入时保留，不擅自删改剧情事实。
- 每段 `text` 仍按原文顺序逐字覆盖，包括拟清理内容；另在该段 `excludedTexts` 中按出现顺序列出要删除的**完整、逐字原文片段**。没有清理内容时填 `[]`。只标出应删的字，不连带删除相邻的剧情句子；不要改写、概括或补写原文。
- `excludedTexts` 是单独的清理记录，不作为剧情资产、分段理由或新工作链；提交后后端核对每处原文并从候选预览及后续工作链剧情正文中剔除，同时保留完整来源范围供追溯。

**通过条件：**所有明确的正文外插入内容均被单独标出；剧情内同形内容完整保留；剔除后每段仍有连贯剧情。

## 4. 关联后续画面与声音需要的已有资产

逐段比对原文与 `assets` 目录，只填写现有的 `characters`、`creatures`、`scenes`、`props` 对应 ID，未确认或目录外资产不能编造；没有合格绑定时填空数组。绑定供后续画面参考和已有人物声音身份使用，不是原文实体清单。图片阶段仍只使用起始画格实际可见的资产参考。

- 先判画面层：真实在场、剧情内拍摄内容中具象呈现、回忆/想象中具象呈现、界面中具象图像，或仅以文字、图标、声音提及。前四类确需身份、空间或独特外观参考时才绑定。
- 表格、排行榜、字幕或聊天记录只出现某人或某物的名字，不等于形象入画；若显示可辨认图像或连续性视觉代表，才按对应资产绑定。
- 具名人物虽仅通过有据的画外对白、消息配音或媒介声音参与本段，但其声音身份在后续剧本和分镜必须稳定，且目录已有对应角色资产时，也关联该角色 ID；后续分镜仍须把此人排除在 `visibleAssets` 和起始可见资产之外。仅被提及而没有实际发声的名字不按此项关联。
- 普通顺手取放或经过的物件若不需独立外观参考，不因名称出现就绑定。实际入画且影响叙事的独特道具、在场人物、生物和取景空间也不能漏掉。

**通过条件：**每段关联的 ID 属于对应类型且与原文可见内容或实际发声身份相符；没有仅因名字出现而误绑，也没有遗漏关键可视对象与已有人物声源。

## 验收与提交

4. 自检所有段落的 `text` 拼接后与本集原文逐字一致，首尾连续且无空段；逐项核对 `excludedTexts` 的原文位置与清理边界，确认清理后的正文仍保留全部剧情；剧情边界、资产关联和用户要求均成立。调用 `submit_plot_split_candidate`，传当前集 `episodeId` 和完整 `segments` 数组，每项为 `{text, excludedTexts, title, splitReason, characters, creatures, scenes, props}`。`text` 必须是连续原文，`excludedTexts` 只包含该段要剔除的原文片段，标题和理由是本段的创作判断。来源位置、原文引用和工作链节点由后端确定性推导，不自行构造或写入文件。
5. 工具失败时依据错误类别、字段路径和修复建议处理。候选数据错误则重读相关原文并修订；版本过期则刷新上下文；权限、服务或不确定是否提交成功时停止并说明。仅在验收有把握时重提，避免盲目反复请求。
6. 工具返回 `pending_confirmation` 后，后端保存候选并在当前会话展示规范化预览。此时停止工具调用，不复述 Skill 或另发一篇报告，也不主动提交正式工作链。

## 用户确认与反馈

7. 用户明确确认当前待确认候选时，本地程序直接将已展示的数据写入工作链和画布并核验；你不会收到一次确认模型回合，也不另发完成报告。
8. 用户提出反馈时，保留原任务、此前已确认约束和本轮修改意见，按需重读上下文并修订候选。重新验收并提交新版，替换本会话旧候选。不要把反馈当确认。
9. 用户只是讨论方案、询问事实或任务对象不明时，正常回答或澄清，不提交候选。
