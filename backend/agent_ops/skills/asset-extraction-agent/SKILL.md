# 拆分当前资产范围

处理已经确认、尚未完成资产分析的一个范围，以已确认断点为本次原文边界。保留本轮用户要求与本会话的修订意见。本次产出是资产身份、复用判断及新资产设计；下面是必须通过的判断阶段，不限定模型请求次数。资料不足、验收失败或提交被拒绝时，自主回到相应阶段补读和修订。

## 1. 锁定任务与资料

先调用 `get_asset_extraction_context(part="source_text")`，读取当前已确认范围的完整原文；多个可执行范围先确认用户所指并指定 `assetRangeId`。再调用 `part="task_state"`，取得范围 ID、提交版本、允许的资产类型和扩展资料目录首页。目录有后续页时用 `part="material_catalog"` 继续发现资料；没有资料则按原文判断，不编造设定来源。此时不必预读所有资料正文。范围未确认、处理中、原文不完整或版本不明时停止并说明；较早的用户要求缺失时只查询本会话历史。

**通过条件：**当前范围、要求和资料完整度明确。相邻原文只用于理解交接；扩展资料只可补足当前原文已出现候选的身份、外观及连续性，不能凭资料新增当前范围没有的对象。资料中“未列入某表”、篇幅或戏份多少等文件组织说明，不是本任务的建卡指令；资产取舍仍依正文实际作用和以下业务标准判断。

## 2. 建立候选并检查覆盖

通读当前范围，把可能需要稳定视觉母版的角色、生物、场景、道具列为候选，记录原文依据并归并明确同指的称呼。候选还不是正式资产；本阶段先防漏、改类、去明显重复，完整价值判断留到下一阶段。

- 稳定身份加充分描述或关系/线索/复用价值、充分可视描述加连续识别价值，均应进入判断；反复互动的角色、生物也要评估。一次性但承担关键冲突、直接伤害、身份核验、仪式/技能、规则揭示、重要交易、特写、主线伏笔或下一段连续性的对象，先记录再判断。
- 单纯提及、清点、购买、持有、浏览、转述或一次性使用不自动成为资产。广告、目录、作者话等非剧情信息不是来源；剧情内屏幕、档案、直播与传闻只是证据载体，其中满足门槛的真实对象仍须评估。
- 人类及人物身份成立的人形主体归角色；非人形活体或稳定物种母版归生物。共享视觉体系且需复用的群体可作母版；普通名单、背景路人、生态和泛称威胁不自动建卡。
- 场景应是可进入、可取景、能供后续分镜引用的完整空间。承载关键行动的普通空间也可能要保留；父级地理范围、角落、门口、局部界面和临时停留点若无独立空间职责，则归属已有场景或分镜。
- 道具候选须可能需要独立视觉管理。普通生活用品、通用工具、设备、纸张、信息载体与临时动作物件通常由角色、场景或分镜承载；不能按物品名称设黑名单。仅出现一次但有独立身份、独特视觉、核心线索识别作用或必须锁定同一外观的生产需要时，仍须保留候选。

**通过条件：**四类及关键一次性对象均有候选或合理排除结论；同一对象的别名、局部名和状态名不重复列项；不凭想象中的外观抬高普通物件价值。

## 3. 先判价值与身份，再决定设计范围

候选形成后调用 `get_asset_extraction_context(part="identity_index")`，只读取已有资产身份；索引截断时继续按类型分页。具体候选的身份、造型或声线需要比对时调用 `get_asset_extraction_asset_catalog`，摘要不足可用文件读取补完整旧设计。身份确需相邻原文时读 `part="adjacent_evidence"`。

扩展资料是可选的设计辅助。已有资料时，先按候选名称及相关别名用 `part="material_evidence", queries=[...]` 查找身份/外貌依据，再结合正文理解；可以合并多个候选的检索。结果有 `nextOffset` 时继续；片段不完整时用返回的 `relativePath`、`lineStart`、`lineCount` 定位正文。名称未命中但目录显示相关人物或设定资料时，按行查看该文件的条目/别名，不以文件名或一次检索未命中断言不存在。无关资料不必通读，非文本格式可有目的地用 `read_project_file` 补充。没有扩展资料或确认没有相关条目时，依据正文上下文完成理解和设计，不要求用户补资料，不因此降低设计完整度。相关资料确实存在但无法读取且影响关键判断时才说明缺口，不以猜测冒充设定。已读有效片段可复用，不反复读取相同内容。

结合原文、相关资料和已有资产，对每个候选决定 `reuse_existing`、`keep_new`、`part_of`、`skip`、`merge` 或 `unresolved` 并记录依据。逐个用已返回身份索引核对规范名、别名及 ID；索引截断时继续分页，设计细节确有需要时再读取详细目录。名称相近不等于同一身份，换名、持有人、地点、服装、损毁及临时状态变化也不自动产生新资产。已有资产复用其 `assetId` 和设计，不借本次拆分静默重设计。

- 角色有稳定身份、明确关系作用、当前行动/对话或后续复用需要时可保存；缺少外貌描写不单独成为跳过理由。同一可视事件中，需要观众持续认出同一参与者才能理解其行动、反应和结果时，已存在制作连续性需要，不要求跨事件再次出场；是否匿名或通过媒介呈现不能替代这个判断。普通背景人物只交代氛围且无需持续识别时仍可跳过。生物须有稳定个体/物种、独立行动、关键生产作用或连续性价值；普通宠物、生态及过场怪物不自动保存。
- 对有稳定姓名或可再次识别的身份者，逐一核对是否与当前人物发生明确关系/冲突、参与现场互动、被当前人物具体回忆，或承担已出现事件的连续性作用；依据足以支持稳定人物识别时应保存或复用，即使此刻没有外貌描写、没有现场对白。人物已故、未进入资料总表或尚无回忆画面，不单独构成跳过理由；仍须核对正文是否已具体建立其身份与关系作用。远方新闻、传闻、背景举例和名单中的具名者，若只说明世界局势、没有进入当前人物关系或可视事件，应跳过；不能仅凭他有独立势力、职务或可能在未来出现就为本范围设计资产。无姓名但与主角直接互动、又被后文明确回指的同一人物，也要按可识别身份判断，不因一次出场而自动跳过。
- 群聊或名单中的具名者，即使彼此有几句对话，也要看他是否与当前人物建立持续关系、独立行动或明确可视出场。只承担界面信息和群体氛围时，保留在剧情与界面文字中；扩展资料对其身份的补充不能替代当前范围的视觉生产依据。
- 场景要区分独立拍摄空间与父级范围、普通附属区域；有稳定外观并需复用的同类空间可合并成类型母版。道具须指出原文或资料实际支持的**独立生产需要**：重复出现、同一人长期使用、情绪意义、局部特写、可交换或可操作，单独都不足以证明应建卡。通过直播、录像或其他媒介完整展示的实体，若以具体外观及操作连续揭示关键规则，仍需稳定视觉母版；评估的是被呈现的实体及其制作连续性，不能仅以“屏幕内样本、无姓名”跳过，也不能把屏幕界面本身另建一套资产。
- 一次性路段、村口、院外等过渡空间，即使承载关键互动，也要先问其是否有需跨镜头保持的独特空间结构或后续直接引用价值；只有行动重要、空间本身普通且不复用时交给分镜，不因出现关键人物就自动另建场景。
- 阵营文字、旗帜、招牌等固定标记若只依附一个场景且无需在不同空间单独锁定同一器物，归入该场景母版或分镜；只有独立器物跨镜头、跨空间连续识别的依据成立，才另建道具卡。名称醒目或可以设计，不等于独立管理需要。
- 能由角色、场景或整体器物母版承载的服饰、标记、固定陈设及普通组成部分用 `part_of`；无需独立母版的临时物件用 `skip` 留给分镜。不能先编造稀有能力、历史或漂亮纹理，再反向证明资产价值。

**通过条件：**每个候选有决定和事实理由；复用身份及 `assetId` 核对有效；场景、道具的独立管理理由清楚。当前原文明确的姓名、亲属身份或其他稳定事实若与旧资产卡冲突，不能只把冲突写在审计备注或完成报告后继续提交。先核对资料，仍无法判定就向用户澄清，等待用户另行授权更正旧资产；**本次资产拆分不得调用 `upsert_asset` 或其他通用写入工具修正旧卡**。任何关键身份或归属未决，都不能假装 `coverageAudit.unresolved=[]`。只有 `keep_new` 进入设计。

## 4. 按类型设计新增资产

只有已经判定 `keep_new` 的项进入设计；此时调用 `get_asset_extraction_context(part="design_context")` 读取制作规格、项目各类资产的视觉方向、阶段视觉和题材语境。项目视觉方向用于落实造型审美，不逐段复制画风指令或生成参数；当前范围的阶段视觉用于限定持续环境。

新建项提供 `name`、`desc`、`assetImagePrompt`、`designRationale`、`sourceEvidence`。复用项提供既有规范名、有效 `assetId`、当前范围原文证据，并把同一身份和复用理由写入 `designRationale`；已有 `desc` 与母版由服务端沿用，不需重新生成。`desc` 说明新资产的身份、叙事作用及稳定特征；新资产的 `designRationale` 区分正文事实、相关扩展资料与视觉设计补全。正文和可选资料共同帮助理解资产：保留已知身份、年龄、关键外貌、结构和世界观；对未写明的可见细节，主动给出符合上下文、商业吸引力与连续制作的一套具体设计，不把资料少等同于只能写普通、简单或无特点，也不把设计补全声称为原文事实。不得为造型编造新身世、能力或剧情。

每个新资产都应有贴合自身的吸引点、清楚的轮廓和少量稳定识别特征，细节密度服从叙事主次，不靠堆饰品或给所有对象同一套华丽模板。视觉母版只写脱离当前事件仍成立的正向可见形态、结构、材质、比例、长期服饰/陈设和识别锚点；不写当前动作、情绪、伤损、天气、临时持物、镜头构图、画幅、分辨率、排除式指令或审查文字。给出确定方案，不用“裙或裤”等互斥选项把设计留到生成时决定。遵循世界观、制作规格与阶段视觉，不把同名不同原理的对象混合设计。

- **角色：**从已知性别、年龄、身份、职业阶层、时代和长期气质中选择明确的视觉人设；把脸型五官、身体比例与轮廓、发型体量、服装剪裁/材质/配色、鞋履及适用妆饰统一成可复现的完整造型，让近景认脸、全身认轮廓。适合商业美型的**成年女性必须**明确落实漂亮、性感、魅惑或潮流等与身份相合的方向；把肩颈、腰线、腿部与鞋履的造型关系设计清楚，性感程度服从正文及身份，不等同于强制暴露。不能只加“漂亮”再套普通路人穿搭，也不能只把方向写在理由中。男性同样要有符合其身份的面部、体态、服装结构和气质吸引点；反派可通过压迫感、精致感或反差形成看点，不凭善恶统一美丑。长辈、劳作者、朴素或粗糙人物保留真实年龄与生活质感，通过骨相、轮廓、整洁或旧化层次、用色和材质形成特色，不强行年轻化，也不能用“普通”免除设计。未成年按年龄设计清晰、自然、有记忆点的造型，不性感化；年龄或性别不明时不擅定具体事实、不套需成年依据的性感方向。群体固定共享轮廓、服饰和标识体系并容纳自然个体差异，不虚构每个人的身份。贫困、劳作、战乱转成有依据的稳定体态、材质旧化或服装体系，不固化一次性受伤或表情。
- **稳定声线：**角色 `voiceStyle` 只写本人日常声线。明确具体岁数才写具体岁数，未知不猜；简短描述可听的性别/年龄感、常态音区及一两个音色质地。不写台词、情绪、当场表演、身份评价、临时变声或凭空添加口音。依据不足可留空。生物只有其本体确有语言交流能力才填写语言声线；普通叫声、理解人话或借声不等于会说话。
- **生物：**按稳定物种来源、尺度、解剖与运动结构设计，头身比例、体表材质和主要附肢形成统一且好辨认的轮廓；选择贴合物种的灵动、威严、奇异等看点，不为独特性随意拼接器官、虚构能力，不把一次攻击、逃跑或受伤写成母版。
- **场景：**使用 `sceneReferenceRole="work_chain_reference"`；设计可进入的空场景，明确空间层级、入口与通行关系、主体区域及少量辨识地标，供后续分镜从不同位置取景。结合材质、配色、固定设施、长期陈设、稳定磨损和有依据的光线形成可辨认的环境气质；不能只列家具或堆“宏伟、精美”。人物活动、临时设备及当前事件不固化为永久设施。
- **道具：**只设计已通过保留门槛的道具；让轮廓、比例、材质对比、工艺及少量关键细节体现用途与辨识度，结构和固定装配足以支持后续使用及状态变化。不写持有者、使用动作、当场位置、特效过程或无依据的特殊能力，不把每件道具都装饰成异宝。

**通过条件：**每个新资产有符合正文及已取得相关资料、可复用、有明确看点的确定母版；角色造型完整，同类主要资产在脸部/轮廓、发型、服装结构或空间/器物结构等方面可区分，不只是换颜色。保留正文明确的相似性，不为区分而改变身份事实。已确认复用的资产不被改写。设计中发现保留依据不成立，应回到第 3 阶段重判，不能用补造外观掩盖问题。

对每个新资产，把已知的关键尺度、主体形态、组成部件、材质色彩及辨识纹样对应到**实际 `assetImagePrompt`**，不能只在说明或设计理由中保留。作者确定的设定与剧情中的传闻、评价、玩笑、示意图分开判断，后者不覆盖前者。

先确定这份视觉母版的目标状态。用户未指定状态时，采用未触发的基础外观；结构、材质和辨识纹样仍须齐全。条件性效果可以留在 `desc` 中供后续状态使用；若要在 `assetImagePrompt` 中表达，就必须同时写清其触发条件、持续方式和强弱，不能只在 `designRationale` 说明条件、却让提示词把效果写成常态。开合器物可说明不同结构状态，但不可混为同一时刻的形态。未来成长形态和能力数值不写成当前外貌。用可见形态转译事实，允许同义表达和有依据的补全，不复制无关设定段落。

目标状态决定当前如何呈现，不删减物体本身的关键设计信息。对于收纳、遮蔽或可展开的部件，实际 `assetImagePrompt` 仍需说明其数量、形状、材质和辨识特征，并注明基础状态下的收纳关系；必要时用清楚分开的结构状态说明，供后续展开设计使用。不能以“当前看不见”为由，只把关键部件特征留在 `desc` 或设计理由中。

## 5. 全量验收、提交和报告

逐类复核当前原文的重要出场和状态都已新建、复用、合并、归属、跳过或澄清；检查身份不重建、类型正确、用户要求落实、设计与制作规格一致。再从正文和已读相关资料反查实际 `assetImagePrompt`：关键外貌是否落实，条件效果是否错误变成常态，是否混入未来或临时状态；同时检查每个资产的具体看点、角色的完整造型与年龄分流、同类资产的结构差异、方案是否确定。适用成年女性只有泛称漂亮和普通穿搭、普通/长辈完全没有识别设计、同类对象仅换色或存在互斥备选时，须修订实际提示词后再提交。允许简洁、含蓄、实用的造型，以是否有具体且统一的设计判断，不以裙装、高跟鞋、首饰或露肤作为统一合格标准。检查可与生成合并，不增加独立审稿调用；不能用正确的说明文字或自称已检查代替实际设计。每条入库资产的 `sourceEvidence` 必须是**当前范围内连续、逐字可查的原文片段**；扩展资料仅作设计依据，不能冒充当前原文；不编造 `sourceRefs` 坐标。将有依据的排除写入 `skippedMentions` 等审计项；只有实际完成核对且无阻断未决时才填 `coverageAudit.checked=true`、`coverageAudit.unresolved=[]`。

提交前再从原文反查一次有稳定身份或后续回指的人物、可供独立取景的空间，以及有固定字样或阵营标记的器物：前两者若未保存须有明确的跳过/归属理由，后者若保存须说明为什么不能由所属场景承载。此项审计针对候选价值，不要求把每个具名者、地点或标记都建卡。

来源引文被拒绝时，按错误字段回到已取得的原文逐字摘录，连同人物名和标点一起核对；反馈中的相似原文只用于定位，须核对对象和语义，不能自动照换。上下文缺失才补读，不凭记忆改一两个字后重试。重提前比较错误字段的实际值，未改变的失败引文不能原样重交。只修正受影响内容及必要关联项，保留其他有效设计。

调用 `submit_asset_extraction_result`，提交 `taskState` 中的 `assetRangeId`、`inputDigest`、`requirementRevision` 和 `assetBatch`。专用读取返回的 `inputDigest` 应一致；原文、已有实际设计、扩展资料（含新增）、项目设置或本会话要求变化时，按反馈重读并重审，不能只换摘要重交旧稿。服务端负责格式、所有权、原文定位、重复身份、版本和写入回读。字段错误按路径回到相应阶段修订；写入状态不明时先核对，不盲目重提。仅在收到 `committed` 和可核验回执后调用 `publish_task_report`，用几行报告处理范围、新增与复用数量及剩余问题。不要粘贴 Skill、工具日志或完整资产数据；无法修复时说明具体阻碍。
