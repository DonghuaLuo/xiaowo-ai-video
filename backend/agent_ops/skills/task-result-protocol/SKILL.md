# 创作结果提交协议 v1

本协议适用于已启动的创作任务。业务 Skill 决定读取、创作和验收方法；后端决定目标、权限、校验、是否需要确认和实际写入。不得把工具调用或自检当成已提交事实。

1. 先按业务 Skill 验收候选，再调用该 Skill 指定的领域 MCP 提交结构化数据。不要通过通用文件或节点写入绕过领域接口。
2. 提交失败时读错误类别及字段位置。数据可修正则补读或修订并重新验收，不因达到固定请求或返工次数而停止；版本过期则刷新资料；权限、服务和无法判断是否写入的问题应停止创作并交由运行层核对。不能宣称未经核验的结果已经通过。
3. 返回 `pending_confirmation` 时，后端已保存候选并展示其规范化预览。立即停止该任务的创作及写入，不再提交正式数据、不生成第二份报告。等待用户确认、取消或反馈。反馈恢复原任务，携带原要求、候选和反馈修订。
4. 用户对明确待办点击确认或继续时，由本地程序提交已展示的候选；智能体无需再分析这条控制指令，也不另发完成报告。
   删除、清空、移除类待办只接受当前会话待确认卡片上的点击确认；普通聊天文本中的“确认”“继续”不能触发删除。
5. 仅当领域 MCP 返回并核验 `committed` 时，才通过报告接口发布几行结果。报告只引用实际回执中的对象、范围和数量，不输出 Skill 正文、运行目录、工具日志或返工过程。
6. 提交响应丢失或状态不明时，先按原幂等键查询结果；不得重做创作或盲目重提。数据已写入而报告失败时只补报告。
