# 视频提示词生成与优化

目标是当前会话里唯一明确的视频节点。工作链生成及其后续反馈修订均使用 `video_prompt_generation` 与 `get_video_prompt_context` / `submit_video_prompt_result`；修订时结合 `currentFinalVideoPrompt` 与本轮用户意见，只更改目标节点分配的镜头。独立卡从关联资料生成使用 `video_prompt_standalone_generation` 与 `get_video_prompt_standalone_context` / `submit_video_prompt_standalone_result`；独立卡已有编辑草稿的优化使用 `video_prompt_optimization` 与 `get_video_prompt_optimization_context` / `submit_video_prompt_optimization_result`。三者不混用，不替用户改换节点。快捷任务使用应用给定的精确节点；自然语言任务若 `activeTarget.nodeId` 或本轮要求已给出实际卡节点 ID，先用该 ID 读取专用上下文并核对镜头组，不要改用画布路线别名或猜测编号；确实无明确目标且存在多个可能节点时再澄清。当前会话中的用户反馈属于本轮要求，不能丢弃。**草稿里的旧创作要求与本轮明确反馈冲突时，以本轮反馈为准；用户已明确允许删减台词或调整镜头表达时，不得再次要求同一项确认。**需要较早的约束而当前上下文没有时，查询当前会话历史。

当前有效引用是本轮资产依据。`excludedAssets` 表示用户明确禁用的身份，不能按“没有可绑定标记的身份”改用普通名称继续写入，也不能从旧草稿、历史、全库或声音资料恢复。独立卡每次生成、优化和再次优化都读取 `asset_names` 与 `references`，核对当前禁用约束；未绑定与明确禁用须区分。若来源的关键动作、对白或既定分镜仍依赖禁用身份，报告具体冲突，停止提交并说明需要调整的上游内容或资产选择；不得擅改工作链分镜或恢复关联。自检覆盖主体出场、动作、发声及引用，不只检查引用标记。

工作链资料包的 `boundaryPlan` 是正式分镜推导出的边界意图和目标输入模式。普通切镜按本组分镜图表达；同空间换机位时，视觉交接图只能作为空间关系参考图，不能写成原生首帧；明确跳时不承接上一段画面。无切镜直续只在单镜组采用原生首尾帧：上一段实际末帧是首帧，本镜终态另有目标尾帧；两者缺任意一个，都应在视频生成前停下准备素材。最终镜头正文明确边界动作与终态，但不得把上一镜尚未完成的动作当作已完成事实；组内逐镜沿用 `entryBoundaryKind` 和 `audioBoundaryKind`，声音交接只沿用正式声音事件，不新增对白或把有意静默改成环境声。静态末帧只能约束图像，不能凭它承诺运动速度连续。

## 统一镜头标准：生成后按同一标准验收

各阶段的已保存结果独立保留，由用户选择是否重做。工作链本轮读取专用接口返回的当前分配分镜；即使会话中另有更新的剧本，也不跨级替换分镜、不以剧本更新为由拒绝本任务或要求先重做分镜。实际输入缺失、资产禁用冲突及本次执行期间输入变化，仍按对应工具契约处理。

一张视频卡对应一次视频生成，卡内可以有多个连续短镜头。模型支持的时长档位约束整张视频卡的成片时长，不约束单镜时长。工作链以本卡分配的分镜为只读边界：镜头数量、顺序、关键画面、台词、画面文字和结束状态均不得擅自改动；视频提示词负责把分镜字段转成模型可执行的自然语言，不再创作第二套分镜。`assigned_shots` 返回的 `sourceShotNos` 是整条工作链里的原镜号，`directorPlanShots[*].shotNo` 与 `submissionShotNos` 是这张视频卡内部从 1 开始的镜号；它们指向同一组镜头，提交 `shots[*].shotNo` 必须使用卡内镜号。`clipDurationSeconds` 是整张卡的成片时长，不是任何单镜的时长。独立卡从本卡草稿或可信连接来源建立镜头边界，再按下面同一标准表达。

工作链的一张视频卡与同组的一张完整分镜图对应，负责把图中本组画格按正式镜序演成一段视频；不把整张宫格当作一幅画面整体运动，也不把画格拆成多个视频任务。

工作链分镜中的 `presentation` 只读保留特殊叙事的实际类型、来源、时间关系、确定程度和入出。类型画格的固定效果已由图片阶段施加；视频提示词只承接当前启用画格的视觉起点和正式镜头的连续动作，不从剧本、`presentation` 的说明或旧字段重新选择、补写、加强效果，也不把同组普通画格写成特殊效果画面。普通现场直接写可见状态和动作，无需写“没有某种效果”之类的自检或排除句。自然语言让观众辨认主客观和事实边界。正式分镜有 `eventLabel` 时，只沿用其 `content` 与已定的起点／镜内出现时机，不把 `sourceQuote` 当作给模型绘制的文字；不创作其他装饰字卡。不把未证实画面写成现实事实，也不靠新增旁白或切镜解释。同一段跨镜的共同事实只需在进入、切换和退出时体现。群聊、直播弹幕、系统界面等媒介信息若同时有画面与人声，写清原载体的文字变化、各说话者的完整发言及同镜人物反应；屏幕字形不承担逐字交付，不把配音写成画内人物已经听见。只有正式分镜的 `screenTextEvents` 明确要求逐字可读时才保留原字。编辑层装饰字卡已退出默认链，不依据旧字段创作、绘制或安排显隐。

本组完整分镜图是供一段视频参考的多画格故事板，不是把整张图当成单幅首帧。按镜号指出对应画格并写执行与切换；已由当前图片和资产引用承担的静态画面、人物外观、布景与剧情背景不在正文里重述。即使上游 `videoExecution` 夹带了起点人物站位、布景或镜尾静态清单，也只提取其中实际发生的动作及必要终态，不逐字转抄；提交前逐镜对照当前画格，删去不影响动作理解的静态复述。只有画格缺失、含糊或与正式分镜冲突时，才补足执行所必需的最少起点锚点并报告图片问题。对画格顺序的实际遵循另由媒体结果验收。

**统一的生成与验收标准**：工作链先读取程序锁定的逐镜时长，再把正式分镜整理为可执行的自然语言；独立卡按其可信来源与本卡时长组织。`video.shots[i].prompt` 是可直接用于生成的镜头正文。后端根据逐镜时间账自动写出“整片时长”和“镜头 N｜起止秒数（本镜秒数）”，正文不要重复镜头标题、整卡时间或字段清单。生成和自验逐项使用同一清单：

1. **起始画面**：工作链已有启用分镜图时，用“第 N 画格起点”承接已有画面，只点名随后要动的主体或与动作有关的载体；不复述整格构图、人物外观、四周环境、屏幕静态栏目、起点已可见的场景文字和已展示的剧情。每写一个分句，检查删去它是否仍能理解新动作、声音同步或必要终态；若能，就删去该分句。资产外观和素材引用由后端按当前绑定另行组装。没有可用图、图中关键起点不明或独立卡实际采用文生视频时，才写出生成所需的最少静态锚点；不能声称模型已看过不存在的图片。画格与正式分镜冲突时报告并走图片修正，不靠长篇文字重画一张图。
2. **可见变化**：从起始画面出发，按先后或因果写清主要动作、表演反应和摄影机行为，直到分镜的可见终态。动作主体、对象、方向和结果明确；动作、运镜和空间关系不互相矛盾。不要为填时长添加空转动作，也不要把一个已确认镜头拆成多个新切点。
3. **声音同步与画面文字**：每句人声保留原字、说话者、画内/画外位置及与可见动作的同时、之前或之后关系。每句台词在本镜自然语言正文**只引用一次**；描述反应时用“发言后半段”等位置关系，不再次摘录同一句的词组，以免视频模型当成第二次发声。起点已可见的文字由画格承担，正文不逐字复述；镜内新出现或变化的场景文字只写载体、变化及关键意思，关键意思已由人声交付时无需再抄一次。群聊或弹幕的讨论声与屏幕消息刷新、主角观看和操作同步，按已定说话者区分声音；屏幕字形不要求与发声逐字一致。表达当镜的语气、适用的口型/表演和媒介声场；环境声、音效和音乐在实际发生的镜头写清触发及相对时间。只有正式分镜明确要求逐字可读的场景字，才写原字与停留时机；快速滚动的普通消息只表达来源和变化。未明确的声音不能补成新台词。
4. **时长与衔接**：工作链逐镜 `durationSec` 必须逐项照抄 `assigned_shots.timingBudget.lockedShotDurations`，最多一位小数，合计等于 `clipDurationSeconds`；这些数字由程序按“本卡当前时长 ÷ 本组正式镜长之和”同比例换算并处理舍入，智能体只使用结果，不读取项目镜头节奏重新计算。卡片时长改变不改正式分镜的镜数、原话、动作和分组；数字缩短不等于声音和动作必能演完，发现明显冲突时指出本镜和卡片时长的制作约束，不擅删原话、补空镜或返回上游按模型档位重分组。动作与对白能同时发生就写在同一画面，不先空转再开口；镜尾可见状态接下一镜起点，末镜不提前演出下一卡。必要节拍用“开始时／说话同时／落句后”表达，不另写与程序时间账冲突的绝对秒数。独立卡没有正式导演镜长，依据本卡可信来源、自然发声和必要动作拟定时间账；内容与卡长冲突时指出最少所需时间。
5. **声音身份与成片正文**：已有角色、生物、旁白的固定声线以本地声音数据为准；只给实际发声且缺少本地声线的临时身份补稳定声线。镜头正文只写动作、运镜、变化、声音原话及其同步、镜尾状态；不要解释人物为什么这样做、复述剧情来龙去脉、证明事实确定程度或逐项盘点起始画面。声音总体要求通过独立的 `sound.soundPrompt` 字段提交，稳定声线通过 `sound.voiceDesign` 与本地声音数据提供；镜头正文仅通过 `video.shots[*].prompt` 提交。后端将声音与自由正文分别保存，不向正文添加声音段或 `【镜头内容】` 标签。最终正文只有生成视频有用的信息，不含 Skill、校验语句、占位符或内部字段名。


**资产名称与正文格式**：写镜头前读取 `asset_names` 和 `references`。前者给出本卡关联资产的真实名称；后者给出当前可绑定的 `assetMentions`（资产 ID 与 `<资产名称>` 正文标记）及必要的视频标记，不给供应商参考图序号。同一角色卡的多视图属于同一身份，实际出场人数以分镜为准。画面出现这些可绑定资产时，正文在相应主体名称处使用返回的原样标记，例如 `<资产名称>转身`；同一资产跨镜出现，在每个相关镜头标记。没有可绑定标记的身份用普通名称，并写必要的可见信息。不得输出界面编辑用的 `@[资产名称]`，也不得在镜头正文描述资产对应参考图、图号、上传顺序、参考卡分区读取方法或重复罗列资产外观及人物介绍。任务卡存储、交给智能体的草稿与智能体返回的镜头正文统一使用 `<资产名称>`；界面编辑时由前端把已绑定名称呈现为 `@[资产名称]`。正式生成时后端验证绑定，并另外组装供应商资产引用段。用户反馈修订时保留仍出现资产的标记，删除不再出现资产的标记。若同名资产导致标记无法唯一绑定，先澄清或调整关联资产，不猜测其身份。

提交前逐镜核对锁定镜长、时间轴、起始画面、观看重点、主要变化、真实声源及镜尾交接。再检查每段停留是否由对白、反应、行动或必要衔接支撑；去掉仍不影响理解的空转动作不应保留。无声镜有独立揭示或因果任务时可以保留。字段齐全不等于声画自然同步；若正式分镜时长或分组无法执行，报告具体镜头与档位冲突，返回上游，不在视频提示词中另造镜头、重排镜长或改写原话。独立卡若核算后仍无法容纳，按用户已授权的删改范围处理，否则说明最少所需时长。

1. 工作链生成优先使用任务输入中的 `preloadedVideoPromptBundle`；仅未提供时调用 `get_video_prompt_context(part="generation_bundle")`，一次取得本节点镜头、卡内/来源镜号映射、整卡时长、可绑定资产与参考图、声音、衔接、模型；目标卡片和输入版本由系统记录。只写本节点分配的镜头；不得混入其他节点，不能因来源镜号与卡内镜号不同而误判镜头分配错误。上下文资料确有缺项才按 `part` 补读。镜头正文以正式分镜的执行、声音和终态为依据；当前启用分镜图提供起始视觉，不再把 `storyboardFrame` 改写进提示词。图与正式字段冲突时以正式分镜为准，并由现有图片重生成或替换流程处理错图。上一卡的末态只用于连续性，不在本卡重演进入该画格之前的动作或场景。缺少有效分配时说明缺口。独立卡生成先调用 `get_video_prompt_standalone_context(part="source_cards")`，每张来源卡仅取一个权威正文；再按需读素材、引用、声音、模型和提交摘要。独立卡优化先调用 `get_video_prompt_optimization_context(part="draft_text")`，读取由应用锁定的本轮编辑草稿；若同时返回 `currentShotPromptPlan`，它与草稿相符，可沿用逐镜边界和时长，再按本轮反馈修订，不必重新从整段文字猜镜头。草稿被手动改写而无该计划时，按草稿重建。再按需读 `asset_names`、`references`、`voice_context`、`target_model` 和 `submission_state`。三种模式只有在修订已保存提示词时才读 `current_prompt`；不从别的卡片或会话猜草稿。独立卡没有结构化分镜分配时，按实际关联输入和用户明确要求组织，不增造剧情、角色或台词。
2. 生成 `video: {shots: [{shotNo, durationSec, prompt}]}`。工作链必须严格保留输入镜头编号、数量和顺序；独立卡生成以关联的本卡来源为依据建立镜头，独立草稿优化按其现有内容和用户明确要求调整镜头。每个 `prompt` 按上方统一镜头标准写成完整自然语言，保留用户本轮修改意见。先验算所有 `durationSec` 的合计，再提交；后端负责把结构化时间账排成可读的连续镜头时间轴。结构化的 `shots` 只是提交及逐镜验收载体，不是让成片提示词退回字段表。
3. 输出 `sound.usedSpeakerIds` 为实际发出人声的稳定身份，无人声用空数组。`sound.voiceDesign.speakers` 只补本次实际发声且没有已保存音色的身份；已有音色不得重写。已关联但缺音色的资产沿用其 `asset:` ID；项目旁白沿用 `project:narrator`。每句表演、语气和声画同步写入对应镜头正文，稳定音色留给声音设计。声音总体要求放入独立的 `sound.soundPrompt` 字段，无额外要求用空字符串；优化时保留当前声音字段中仍然适用的要求，不抄进镜头正文，也不重复列出已有稳定声线。不得由画面主体、内心活动或屏幕文字推断新增说话者。
4. 按上方**同一套统一镜头标准**逐镜验收，再核对对应工具的字段契约与目标模型字符上限。工作链另核对分配边界及镜号；独立卡生成核对连接来源和引用绑定；独立卡优化核对本轮编辑草稿的剧情与引用绑定。没有用户要求的事实不能丢，只保留对生成有用的信息。不能满足某项要求时先自行修订结果。
5. 工作链调用 `submit_video_prompt_result`，独立卡生成调用 `submit_video_prompt_standalone_result`，独立卡优化调用 `submit_video_prompt_optimization_result`；只提交 `video`、`sound` 两个顶层对象：`video` 包含 `shots`，`sound` 包含 `soundPrompt`、`usedSpeakerIds`、`voiceDesign`。已有锁定目标时读取工具只传 `part`；普通聊天没有锁定目标时，首次读取可额外传用户明确指定的 `nodeId`，系统验证当前画布中的实际卡片后锁定目标，后续读取可省略。普通聊天优化以该卡已保存的正文和声音为草稿；编辑弹窗发起的优化使用弹窗草稿。最终提交不携带 `episodeId`、`nodeId`、`inputDigest`，目标与读取版本由系统提供。后端校验输入版本、声音及镜头契约，组装最终提示词并写入目标节点。独立卡成功提交会立即落库，无需另发保存指令。字段错误按返回路径修订后重提；上下文变化先重新读取；写入状态不明时停止并说明，不能盲目重提。
6. 仅收到正式 `commitReceipt` 后调用 `publish_task_report`，用几行说明目标、镜头数量、已更新位置和必要风险。工作链 `generation_bundle.hasStoryboardReference=false` 时仍可按正式分镜提交文本，但须在报告里说明当前没有可用分镜图作为媒体起点；不要把这句话写进视频提示词正文，也不要声称已检查图片。报告后停止，不在对话中粘贴 Skill、完整 JSON、模型请求或工具日志。
